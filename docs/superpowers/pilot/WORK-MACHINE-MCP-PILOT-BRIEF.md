# Бриф №4: MCP-пилот (рабочая машина) — агентное использование + эмбеддинги

> Задание для Claude Code-сессии на рабочей машине. Пользователь скажет: «прогони MCP-пилот по
> этому брифу». Это ПЕРВЫЙ прогон (а) с эмбеддингами на боевом корпусе и (б) агентного
> использования графа — верификация №7 мастер-плана («подключить MCP к Claude Code и вживую
> спросить»). Baseline чисел — `docs/superpowers/reports/2026-07-24-pilot-rerun-3.md`.

## 1. Предусловия

`git pull` (HEAD ≥ 9d3e56c) → `docker compose up -d` → `uv sync --extra local-emb` →
`uv run codegraph doctor` → смоук: `uv run pytest -m "scip and falkordb" tests/eval/test_m9_gate.py
-q --junit-xml=/tmp/g.xml` (оба кейса зелёные = M9-механизмы работают здесь).

## 2. Полный индекс С эмбеддингами (впервые на боевом корпусе)

В workspace yaml включить RU-рекомендацию README:
```yaml
embedding:
  provider: local
  model: intfloat/multilingual-e5-base
  query_prefix: "query: "
  passage_prefix: "passage: "
```
`codegraph index <ws>` — БЕЗ `--no-embed`. Первый прогон платит полную стоимость эмбеддинга
(префиксы вшиты в model_id → старый кэш стенда не подойдёт — это не коллизия, а честная смена
модели); повторные прогоны — persistent cache по input_hash (embedded_fresh≈0). Зафиксировать
времена (индекс/эмбеддинг отдельно) и счётчики.

## 4. MCP-регистрация и агентные сценарии (верификация №7)

`claude mcp add -s user codegraph -- uv run --directory <репо> codegraph serve <ws.yaml>` →
новая Claude Code-сессия → `graph_stats` работает. Затем агентные сценарии (фиксировать: ответ
агента, какие MCP-инструменты вызвал, галлюцинации/миссы):

1. **Трасса**: «проследи, что происходит после <реальный вход re-run №3>» ×4 входа — агент обязан
   собрать цепочку из trace_process (не из grep) И озвучить внешнюю границу (external_exit_count).
2. **Поиск**: «где обрабатывается X» — 6-8 RU-вопросов по коду (ожидание hit@8 ≥ 7/8 по M5-эксперименту
   с e5; фиксировать ранги через `codegraph eval retrieval --exact` на тех же вопросах отдельно).
3. **who_calls**: «кто вызывает Y» ×3 — сверить полноту против grep вручную.
4. **Карточки**: get_source/expand_neighbors хендлера — композитный путь виден агенту.

## 5. Диагностика dispatch.* (беклог-вопрос)

Попросить агента (или напрямую): `SELECT dst FROM dropped`-анализ — префиксы 167 dropped
CALLS-рёбер (`report.json` / staging): динамические плагины? Зафиксировать топ-префиксы для M10.

## 6. Ограничения для агента (озвучить в сессии)

- НЕ поднимать `min_confidence` выше 0.5 в trace_process (presence-фильтр выкинет external-выходы
  целиком — граница исчезнет и из счётчика; документированное свойство).
- `--incremental` при правке mount-файлов: редкий edit-shape «все mounts удалены» оставляет stale
  композитный путь в props (TRACKED, M10); full-реиндекс лечит.

## 7. Отчёт — две версии (правило прежнее)

`docs/superpowers/reports/<дата>-mcp-pilot.md`: полная (остаётся) + SANITIZED (числа, времена,
латентности MCP-вызовов, вердикты, галлюцинации-без-имён) — коммит+push. Отдельная секция:
«что агент понял неверно / чего не хватило в инструментах» — вход для M10.
